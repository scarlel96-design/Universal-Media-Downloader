# Clean-room 구현 사양

이 문서는 4K Video Downloader+의 코드에서 옮긴 설계가 아니다. 입력은 우리 설계서 V1.1, 공개 제품 설명, 그리고 yt-dlp, gallery-dl, HTTPX, FFmpeg, Playwright의 공개 기능이다. 의사코드나 내부 문자열은 보지 않았다.

## 하지 않을 것

- 4K 바이너리, QML, 아이콘, 리소스 문자열을 복사하지 않는다.
- 4K 라이선스 검사, 업데이트 서버, 인앱 스토어를 호출하지 않는다.
- 4K JSON 내보내기를 호환 형식으로 읽지 않는다.
- DRM 해제, 인증 우회, CAPTCHA 자동 해결을 넣지 않는다.

## 동작 계약

1. 사용자는 HTTP(S) URL 하나 이상을 넣는다. 다른 스킴과 사설·루프백·링크 로컬 주소는 기본 거부한다.
2. 범위 기본값은 현재 게시물이다. 추천, 다른 게시물, 사이트 전체로 확장하지 않는다.
3. 직접 미디어 URL이면 바이트 시그니처와 MIME으로 후보 하나를 만든다.
4. 알려진 영상·갤러리 호스트는 yt-dlp 또는 gallery-dl의 메타데이터 모드를 먼저 호출한다. 실패하면 이유를 보여 주고, 사용자가 브라우저 렌더를 승인한 뒤에만 Playwright를 연다.
5. 그 외 HTML은 본문 컨테이너(`article`, `main`, JSON-LD) 안의 이미지만 높은 점수로 둔다. 광고, 아이콘, 프로필, 트래킹 픽셀은 제외 목록에 남기고 한 번에 되돌릴 수 있다.
6. 후보 필드는 설계서의 `MediaCandidate`를 따른다. `blob:` URL은 저장 URL이 아니다.
7. 사용자가 고르기 전에는 원본을 저장하지 않는다. 미리보기는 작은 이미지만 받는다.
8. 저장은 `.part`에 스트리밍하고, 길이와 해시 검사가 끝난 뒤에만 최종 이름으로 옮긴다. ETag나 길이가 바뀌면 이어 붙이지 않는다.
9. 동시성은 전체 상한과 호스트 상한을 따로 둔다. 429와 Retry-After는 그 호스트만 늦춘다.
10. 취소는 해당 HTTP 요청과 자식 프로세스를 멈춘다.
11. 작업 상태와 이력은 SQLite에 남긴다. 토큰 원문은 넣지 않고 OS 자격 저장소 참조만 둔다.
12. 프록시는 사용자가 켠 경우에만 쓰고, 실패하면 직접 연결로 바꾸지 않는다.
13. YouTube Data API는 재생목록 메타데이터에만 쓰고, 그 토큰을 파일 다운로드 권한으로 보지 않는다. 다운로드는 권리와 서비스 조건이 허용하는 경로에만 보여 준다.

## 엔진 경계

| 필요 | 담당 | 직접 만들지 않는 이유 |
|---|---|---|
| 사이트별 영상 추출, 포맷 목록, 자막, HLS/DASH | yt-dlp | 공개 추출기가 이미 있다 |
| 갤러리·이미지 호스트 | gallery-dl | 동일 |
| 단일 파일 HTTP, Range, 재시도 | HTTPX | 표준 HTTP |
| 병합, 길이, 썸네일 | FFmpeg, ffprobe | 설계서가 재사용을 지정 |
| JS 렌더 | Playwright | WebEngine을 제품에 넣지 않음 |
| 큐, 필터, 미리보기, 창 | 이 저장소 | 제품 UX는 공개 엔진에 없다 |

## 창

Windows 캡션 버튼, 시스템 메뉴, Snap, Alt+Space, Alt+F4는 OS와 Qt 기본 프레임에 둔다. 도구막대는 캡션 아래의 클라이언트 영역이다. 프레임리스 창은 스냅이 검증되기 전에는 쓰지 않는다. 자세한 계약은 `docs/design/WINDOW_HOST_CONTRACT.md`.

## 완료 기준

WO-01은 고정 HTML 픽스처에서 본문 이미지 수와 순서가 맞고, 광고·프로필이 기본 결과에서 빠지며 복원되고, 취소와 재시작 후 이력이 남는 것이다. 경쟁 제품과 속도가 같다는 기준은 없다. 그 측정은 PERFORMANCE_BASELINE.md에 따라 아직이다.
